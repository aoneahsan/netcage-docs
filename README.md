# netcage-docs

Documentation site for **NetCage**, a per-app firewall for Android.

Its address is **https://netcage-docs.aoneahsan.com**; product site
**https://netcage.aoneahsan.com**; Play package `com.aoneahsan.netcage`.

> **The product and documentation sites are live.** GitHub Pages serves the docs at the custom
> domain above with HTTPS enforced. The public source stays in this repository; product internals and
> credentials remain in the private app repository.

Built with [Docusaurus](https://docusaurus.io/) 3 and deployed to GitHub Pages by
`.github/workflows/deploy-pages.yml` on every push to `main`.

## Local development

```bash
yarn install
yarn start          # dev server with hot reload
yarn build          # production build — this is the gate
yarn serve          # serve the real build, which is what gets deployed
yarn typecheck      # tsc
```

`yarn build` is the link checker: `onBrokenLinks`, `onBrokenAnchors`, `onBrokenMarkdownLinks` and
`onBrokenMarkdownImages` are all set to `throw`, so a link to a page that does not exist fails the
build rather than shipping a 404.

## Writing a page

Pages live in `docs/` and the sidebar is autogenerated, so a new file appears without editing
`sidebars.ts`. Every page needs front matter:

```markdown
---
title: How it works
description: The sinkhole VpnService NetCage is built on, and the invariant that keeps it safe.
sidebar_position: 2
---
```

`title` and `description` are not optional — without them the page is unsearchable and ships an
empty meta description. `sidebar_position` sets the order.

## 🔴 This repository is public

No `.env`, no key, no credential, no token, ever. `.env.example` carries names and empty values
only. Analytics is env-gated: with no `GOOGLE_ANALYTICS_ID` in the environment the plugin is not
loaded at all and the site behaves identically.

## Content rules

Two apply to every page, and both come from the product:

- **NetCage is never described as an ad blocker or a content blocker.** It does no domain filtering,
  no hosts file and no DNS interception. It blocks an app entirely or not at all. Play's Device and
  Network Abuse policy treats per-app firewalling as a device-security exception; ad-blocking
  framing is not covered by it.
- **Nothing is claimed that the app does not do.** Facts come from the app repository — its
  `README.md`, `docs/play-store/` and the app's own `strings.xml`, which is where control names come
  from. A menu path invented here is worse than a page that omits it.

## Deployment

Push to `main`. The workflow builds and publishes; `static/CNAME` pins the custom domain.

DNS (`netcage-docs` CNAME → `aoneahsan.github.io`) and the Pages custom-domain setting with
**Enforce HTTPS** are one-time owner steps, tracked with the app.
